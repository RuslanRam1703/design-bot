# Единый план Design Assistant — актуализация 2026-11-10

Статусы: **DONE** — код объединён с main; **LIVE** — подтверждён Render; **PARTIAL** — часть сценария реализована; **TODO** — не завершено; **VERIFY** — нужен реальный E2E. CI не равен реальному пользовательскому тесту.

## Продуктовые границы

Один Telegram-бот + Mini App + административный интерфейс. Единая сущность заявки (lead ID) связывает калькулятор, клиентский бриф, материалы, статусы, сообщения, проекты и приватный архив. Не создавать второй независимый реестр заявок или отдельную историю сообщений для архива. Бесплатный Render, постоянное хранение Upstash; не публиковать ID закрытых групп, ссылки-приглашения и токены.

## Приоритет ближайших пакетов

1. Контакт без username и тесты UI-контракта.
2. Маршрутизация клиентского ответа по конкретной заявке, без потери уже работающего общего обращения.
3. Контекстная карточка в архивной теме с действиями и безопасным ответом.
4. Retry/outbox архива и E2E.

## Ограничения

- Bot API отправляет сообщения от имени бота, а не личного аккаунта владельца.
- Прямая ссылка по ID не гарантирует доступ к профилю при ограничениях Telegram.
- Отправка клиенту через бота возможна после взаимодействия пользователя с ботом, пока бот не заблокирован.
- Smoke-проверка Telegram API не доказывает прохождение клиентского Mini App.
- Существующие действия в админке повторно не реализовывать; расширять их.
