# Design Assistant

Существующий Telegram-бот и Mini App для портфолио, предварительного расчёта,
брифа, заявок и общения дизайнера с заказчиком.

- Бот: [@designtant_bot](https://t.me/designtant_bot).
- Production: https://design-bot-ebie.onrender.com.
- Стек: Python 3.12, aiogram 3, aiohttp, JavaScript.
- Инфраструктура: существующий Render Free и Upstash Redis REST.
- [Текущий план и ограничения](docs/PRODUCT_ROADMAP.md).

## Запуск и данные

Production получает обновления через защищённый Telegram webhook
`/telegram/webhook`. Polling не используется. При запуске инициализируется
хранилище, регистрируются webhook и меню; ожидающие обновления не удаляются.
Секрет webhook проверяется до обработки запроса.

`UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` включают постоянное
хранение контента, заявок, переписки и FSM. Без них применяется локальное
хранилище для разработки, непригодное для сохранения production-данных на
эфемерном диске Render. Не удаляйте ключи Redis и не запускайте повторный seed
в существующей базе. Существующие записи совместимы с новыми полями.

Для локальной разработки установите зависимости `pip install -r requirements.txt`
и заполните `.env` по `.env.example`. Полный запуск: `python -m bot.main`;
нужны отдельный тестовый бот и доступный Telegram HTTPS-адрес. Не запускайте
локальную копию с production-токеном: она может изменить webhook рабочего бота.
Не коммитьте `.env`, токены, приватные ссылки или идентификаторы групп.

## Работа владельца

`/admin` доступен только владельцу. Основные разделы — заявки, проекты,
контент, услуги и цены, пользователи и доступ, настройки и данные.

1. **Заявки:** список → карточка → «Написать заказчику». «Переписка» открывает
   входящие и исходящие сообщения, даты и статусы. «Материалы» позволяет
   получить файлы из заявки и свободной переписки.
2. **Ответ из приватного архива:** откройте тему заявки и отправьте
   `/reply текст`. Адресат определяется только по постоянной привязке темы.
   Команда другого пользователя или другой группы игнорируется.
3. **Несколько заявок у клиента:** бот предлагает выбрать нужную. Исходный
   текст/подпись сохраняются до выбора; одно сообщение нельзя прикрепить
   к двум заявкам. Архив — вторичная копия, основная история хранится в Redis.
4. **Портфолио:** фото или фотоальбом настроенного публичного канала создаёт
   черновик. Затем «Контент → Кейсы → Редактировать» и «Статусы и публикация»:
   проверить галерею/описание, выбрать категорию, опубликовать. Черновики,
   отклонённые проекты и корзина не попадают в публичное API.
5. **Услуги/FAQ:** редактируются в существующих административных разделах.
   Цены Mini App и серверного расчёта используют то же хранилище.

Ответ через бота работает без username, если клиент запустил бота и не
заблокировал его. Прямая ссылка на профиль по ID зависит от Telegram.
`sent` означает принятие сообщения Telegram, а не прочтение человеком.
`unknown` и оставшийся после сбоя `sending` означают неподтверждённую доставку:
перед новым ответом проверьте переписку. Автоповтора таких ответов нет,
поскольку Telegram Bot API не предоставляет ключ идемпотентности отправки.

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN`, `DESIGNER_CHAT_ID` | Доступ к боту и проверка владельца |
| `WEBAPP_URL`, `PORT` | Публичный адрес и порт HTTP |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | Постоянные данные и FSM |
| `PORTFOLIO_CHANNEL` | Публичный источник портфолио |
| `MEDIA_ARCHIVE_CHANNEL` | Публичное размещение загружаемых обложек |
| `CLIENT_MATERIALS_CHANNEL` | Приватная форум-группа клиентского архива |
| `PRIVATE_MINIAPP_CONTENT` | Требовать подписанную Telegram-сессию для контента |
| `R2_*` | Существующий дополнительный путь хранения изображений |

Клиентские файлы не публикуются в публичном канале обложек. URL Bot API,
содержащие токен, не выдаются браузеру. Новых платных ресурсов для этой версии
не требуется. Настройки production меняются отдельно от кода после проверки
последствий. `ARCHIVE_SMOKE_TEST_ID` запускает реальную отправку в архив;
не устанавливайте его для обычного тестирования или без разрешения владельца.

## Проверка поставки

CI: Python unittest, проверка синтаксиса JavaScript, Node UX-тесты.

```bash
python -m unittest discover -s tests -p 'test_*.py'
node --check webapp/js/app.js
node --test tests/test_webapp_ux.cjs
```

Для проверок нужны непустые тестовые `BOT_TOKEN`, `DESIGNER_CHAT_ID`,
`WEBAPP_URL`; CI задаёт синтетические значения. Тесты используют временное
хранилище и mock Telegram. Не подключайте production Redis к тестам.

`GET /health` отвечает `ok` без записи в данные и обращений к Telegram.
Заголовок `X-App-Revision` содержит SHA из стандартной переменной Render
`RENDER_GIT_COMMIT`, если она доступна. Сравните его с `main`, затем проверьте
статус deploy и ошибки в Render. HTTP 200 подтверждает работоспособность HTTP,
но не доставку Telegram и не доступность каждой зависимости. Render Free
может засыпать; приёмка после пробуждения выделена в ручной чек-лист.

## Оставшаяся приёмка

Реальные Telegram-сценарии и мобильная визуальная проверка остаются
`MANUAL TEST PENDING`. Журнал копирования в архив хранится вместе с заявкой. Подтверждённые ошибки
повторяются с задержкой (до пяти попыток), либо вручную кнопкой в карточке.
Неопределённые результаты не повторяются: сначала владелец проверяет архив.
Сбой архива не удаляет основную историю. Фоновая обработка возобновляется,
когда сервис Render Free просыпается. Полная приёмка не объявляется по одному CI.


## Экран запуска после сна Render

HTML/CSS/JS существующего Mini App можно публиковать отдельно как Render Static Site
(тот же репозиторий, ветка main), не создавая второй бот или хранилище.
Сборка без дополнительных библиотек: `python3 scripts/build_static.py`,
каталог `static-dist`, `APP_API_ORIGIN` — HTTPS-origin существующего backend,
`SKIP_INSTALL_DEPS=true`. Экспортируются только `webapp` и явные страницы запуска;
production-данные, `.env` и серверный код в публикацию не попадают.

`MINIAPP_URL` на backend задаёт новый адрес меню и inline-кнопок. **WEBAPP_URL
не меняется:** на нём остаётся `/telegram/webhook`. Сервер разрешает CORS только
новому frontend и своему origin; подпись initData и права клиента проверяются
как раньше. URL Main Mini App в BotFather, если он настроен отдельно,
не обновляется методом `setChatMenuButton` — его нужно сверить отдельно.
Старые сообщения с прежними URL остаются рабочими, но их первый переход может
показать экран Render, пока старый backend просыпается.

Лоудер — inline SVG/CSS с медленным движением, без видео, шрифтов с CDN и
анимационных библиотек. Поддерживается reduced motion; анимация и проверки
готовности приостанавливаются в фоне. Только GET `/health` повторяется с
ограниченной частотой до 90 секунд; HTML-страница Render даже с HTTP 200 не
считается готовностью API. POST заявок автоматически не повторяется.

Одноразовый `/draft-bridge` пытается перенести локальный черновик со старого
origin: проверяются точные origin и окно iframe, существующий новый черновик
не перезаписывается, старый не удаляется. При блокировке стороннего storage
браузером или тайм-ауте (1,5 секунды) приложение продолжает загрузку; старый
черновик остаётся доступен по прежнему адресу. Переадресации Telegram-сессии,
передачи initData в URL и service worker не используются.

Откат: очистить `MINIAPP_URL` и развернуть backend. Меню вернётся на прежний
адрес; данные/Redis и webhook не меняются. Проверка холодного запуска в
реальном Telegram остаётся отдельной ручной приёмкой.
